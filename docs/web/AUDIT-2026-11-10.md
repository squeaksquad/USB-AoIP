# Web page and access: audit and proposal

For the operator to pick from. 2026-11-10, packaging workstream 3. Nothing
has been changed. Sources: a read of `web-ui/` and `web-control/`, a read of
the pinned Inferno and Statime sources in `dante/upstream/`, and a look at
the page in a browser (desktop and 375 px wide) served by the real
`usb16x16-web` against a mock Dante stack. Nothing was run on the Pi.
Line numbers are at commit `install/from-scratch` HEAD.

Severity: **B** blocks or endangers a new user, **M** misleads, **C** cosmetic.

## Part 2. Access: what is wrong today

Read from code; none of these was exercised.

| # | What | Where |
|---|---|---|
| S1 | **The web user can make root overwrite files.** The root applier writes `current.json.tmp`, `rate-history.json.tmp`, `apply.lock` and `presets/check-<id>.dsp` with plain `open()` in a directory the web user owns, and `receipts/` sits under a parent the web user can rename. A symlink planted at any of those names makes root truncate, write or create a file anywhere. Whether that reaches root code execution was not shown; treat it as if it does. | `usb16x16-apply:161-169,591-592,792,1796,2079` |
| S2 | **Any web page can drive the unit through a signed-in browser.** No Origin or custom-header check: a page on another site can POST Apply, a preset of its own (output gain up to +40 dB passes the guards), or shutdown, and the browser attaches the Basic credentials. | `usb16x16-web:1432-1442,1523-1532` |
| S3 | The password crosses the network in clear on every request (Basic over HTTP). | by design; `web-control/README.md` "What Basic auth over plain HTTP does" |
| S4 | The applier trusts spool input more than it should: unbounded reads through symlinks (`/dev/zero` is a memory DoS), no `O_NOFOLLOW` or ownership check, kind `rate` accepted from the web spool though the page has no such route, a malformed `rate-history.json` raises uncaught, root writes a temp file into the audio user's runtime directory with plain `open()`. | `usb16x16-apply:763,926-931,1727,1810,1988` |
| S5 | The bind address is chosen once at start. With no address on the management interface yet it falls back to 127.0.0.1 and stays there until restarted. IPv4 only. | `usb16x16-web:390-397,2022` |
| S6 | No handler timeout and `TasksMax=64`: idle connections can exhaust the service. No security headers. The unit is well sandboxed but lacks an empty capability set and several cheap directives; the two root apply units have no sandboxing. | `usb16x16-web.service:33-49` |
| S7 | Statime runs as root with no sandboxing, and its clock socket `/tmp/ptp-usrvclock` is world-writable: any local user can register as a clock client. | `usb16x16-statime.service`, `usrvclock-rs/src/lib.rs:285-292` |
| S8 | A bug in workstream 2's installer: `set-password` runs `--add-user` as the web user, which must create a temp file in a directory the installer made root-owned. It would fail on a fresh install. | `install/install.sh` `cmd_set_password`, `usb16x16-web:1198-1209` |

## Part 3. Proposal

### A. Requests from the page to root

Two directories instead of one, neither owned by the web user:

- **Inbox** `/var/spool/usb-aoip/inbox`, `root:<web group>` mode `1730`: the
  web user can create files and cannot list, rename or replace anyone
  else's. The page's service writes `<id>.request` and, for an upload,
  `<id>-<rate>.dsp` beside it, each under a fresh random id.
- **Outbox** `/run/usb-aoip-apply`, `root:root` `0755`: `current.json`,
  receipts, the lock and the rate history. The web service reads
  `current.json`; it writes nothing here. The loader check's temp file moves
  to a root-only directory.
- The applier opens every inbox file `O_NOFOLLOW`, checks it is a regular
  file owned by the web user, reads a bounded number of bytes, and removes
  it. It validates the envelope before any kind acts, and takes `rate` only
  from the rate-request trigger. The write into the audio user's runtime
  directory becomes `O_EXCL | O_NOFOLLOW`.
- `usb16x16-apply.path` watches the inbox directory (`DirectoryNotEmpty=`)
  instead of one file name.
- Light sandboxing on the two root units (`ProtectHome`, `PrivateTmp`,
  `NoNewPrivileges`, `ProtectKernel*`), nothing that could stop a restart.

A unix socket instead of a spool was considered: it removes the file
handling but needs a long-running root listener or socket activation, and
loses the "request survives a service restart" property the page's pending
logic uses. The spool with the fixes above is smaller.

### B. The HTTP surface

- Every state-changing request must carry `Content-Type: application/json`
  and a custom header, and an `Origin` that matches the `Host` when a
  browser sends one. That closes S2 without sessions or tokens: a cross-site
  page cannot set either without a preflight the service never answers.
- `X-Content-Type-Options`, `Content-Security-Policy` (self only),
  `frame-ancestors 'none'`, `Referrer-Policy`; a socket timeout.
- `WEB_BIND` in `install.conf` for an explicit address; otherwise the
  management interface's address, and when it has none the service exits
  non-zero and systemd retries, instead of sitting on loopback.
- Journal access by group `systemd-journal` instead of `adm`; the missing
  sandbox directives added, those that could affect `vcgencmd` tried first.

### C. TLS: the operator's decision

| Option | What it gives | What it costs |
|---|---|---|
| **1. Self-signed certificate by default** (recommended) | The password and every request encrypted. The installer generates a key and certificate for the unit's hostname and addresses with `openssl` (already on Raspberry Pi OS); the service wraps its socket with the standard library's `ssl`. `WEB_TLS=self-signed\|provided\|off`, and `provided` takes your own certificate paths. | A browser warning on first visit to each unit, accepted once per browser. The certificate must be regenerated if the address changes. No new dependency. |
| 2. Plain HTTP, documented | Nothing new to trust or renew; today's behaviour. | The password is readable by anyone on the management network, every request. Acceptable only on a network you fully control, and the README has to keep saying so. |
| 3. TLS only when a certificate is provided | No warning ever shown by default. | Off for nearly everyone, so the same as 2 in practice. |

A real certificate from a public authority is not available for a device
on a private address without the owner running DNS for it; that is what
`provided` is for.

### D. First-run password

`install.sh set-password NAME` stays the way (it prompts twice, never takes
the password on a command line), fixed so it works: the login file moves to
`/etc/usb-aoip/web-auth`, `root:<web group>` `0640`, written by root and only
read by the service. `install` ends by asking for a first login when run at
a terminal. An in-browser first-run setup was considered and not proposed:
it needs a one-time token and an unauthenticated route, more surface than
the problem deserves.

### E. Statime: touches the audio path, so opt-in

Both ends are configurable without a patch: Statime has a `usrvclock-path`
config key, and Inferno takes `CLOCK_PATH` in its ALSA config. The proposal:

- a dedicated user with `CAP_NET_BIND_SERVICE` and `CAP_NET_RAW` only (it
  never sets the system clock in this configuration), the usual sandboxing,
  and the socket at `/run/usb16x16-statime/ptp-usrvclock`;
- one trap: the Inferno client binds its own reply socket in `$TMPDIR`
  (`/tmp`), and a non-root Statime must be able to write to it, so the two
  services need a shared group, a shared runtime directory as `TMPDIR` for
  the owner, and a umask.

This changes bytes in three accepted files (the Inferno config 85a5256f,
the Dante unit 27b68877, the Statime unit and config) and the clock is what
everything else hangs on. It cannot be verified off the Pi. So: implemented
behind `PTP_SANDBOX=0|1` in `install.conf`, default 0, which renders exactly
today's files (the render test keeps proving it). You try 1 on the Pi; the
default flips only after it has passed your battery.

### What the applier and web changes mean for acceptance

A to D change `usb16x16-apply` (347a7062) and `usb16x16-web` (6b98e7cf) and
their units. Neither is in the audio path; by the 2026-10-29 rule they are
accepted on their own behavioural checks plus a noise probe and one
two-minute soak. The unit tests in `web-control/` run in CI; the symlink
and cross-site cases get tests of their own.
